# MMO Skill Demo Agent Notes

- Keep `./docs/world-building.md` updated when towns, factions, anchors, zones, NPC roles, creature ecology, reputation rewards, crafting materials, quest arcs, relics, hostile motives, live events, boss motives, or major world relationships change.
- Keep `./docs/world-travel.md` updated when travel hubs, route labels, route costs, escorts, faction shortcuts, movement unlocks, reputation gates, blocked reasons, or travel UI behavior change.
- Keep world-building notes high-level. Prefer setting intent, relationships, desires, goals, and player-facing meaning over code-heavy implementation details.
- If world data and docs drift, treat runtime behavior as canonical, then update `./docs/world-building.md` to match.
- When zones or anchors change, update `./docs/world-building.md` with real `zoneId` names and say whether any older legacy zone behavior still constrains them.
- When route behavior changes, update `./docs/world-travel.md` with the player-facing network rule, cost, gate, and current implementation boundary.
- When faction quests change, document player-facing faction desire first, then current quest spine or future chain intent.
- When crafting changes, document recipe choice honestly: picker UI, station grouping, blocked reasons, or current first-valid interaction behavior.
- When visual work changes, document what players can read on screen through terrain, anchors, spawn mix, silhouettes, motion, HUD, or Codex. Do not claim unique art exists before it does.
- For numeric tuning, update authored base values or data tables directly. Do not add runtime scaling helper layers for one-off size, speed, distance, radius, or percent changes; live buffs and temporary status modifiers are the exception.
- Treat controller play as a first-class acceptance path. New combat, HUD, panel, travel, inventory, gear, skill, quest, market, or dialog surfaces must be reachable and reversible without mouse input.
- For PlayStation-style controller UI, keep a consistent mental model: left stick or D-pad moves focus, X confirms, Circle cancels or backs out, shoulder buttons move tabs/pages, right stick keeps gameplay aim when focus is not in a text-like UI.
- Any controller-facing HUD or panel needs a visible focus indicator, stable focus order, and prompts that reflect the active input mode. Never leave focus on hidden or offscreen elements.
- Avoid analog-only UI interaction. If a HUD affordance can be hovered, dragged, aimed, or clicked with a mouse, provide a digital controller route with single, non-simultaneous presses.
- Keep controller stick deadzone configurable and persisted. Default to 5% unless a playtest-backed reason changes it.
- When controller bindings become configurable, update every visible hint, tutorial cue, hotbar label, and control map to read from the active mapping instead of hard-coded key names.
- For large landmark passes, keep at least one dominant silhouette, multiple unique props, and service/danger reads per screenshot-covered area.
- Keep curated runtime world art notes in `./assets/world/NOTES.md`, with source archives under `./assets/source/craftpix/` and world-building meaning summarized in `./docs/world-building.md`.
- Use `bun.cmd run screenshot:world` to refresh outdoor area screenshots after large visual terrain, landmark, or sub-town changes.
- Keep a clear remaining-boundaries note when expansion data exists before full terrain, questlines, recipe picker UI, or visual assets.
- Surface expanded faction data through catalog and UI surfaces before adding isolated lore-only screens.
- Implement reputation and materials incrementally through existing inventory, quest, renown, reward, vendor, and crafting-adjacent loops before inventing standalone systems.
- Preserve existing world-zone constraints for new map anchors until real new zones are added; use lore, catalog data, quest flavor, travel hints, or compatible constrained encounters in the meantime.
- For repeatable world/content work, prefer deterministic Bun TypeScript scripts that scan, score, generate snippets, update docs, or emit handoff packets before asking AI to reason manually. Keep AI focused on WHY, selection, review, and integration; update the local script surface when the same step repeats.
