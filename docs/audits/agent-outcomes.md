## Substrate audit

The existing substrate was stronger than the failure description alone suggested.
The guidance checker found 42 skills and 109 instruction/route files before this
change, with no metadata or link errors. Root/nested instructions already owned
scope, portability and autonomy; specialized workflows already supplied real
browser inspection, artifact acceptance, bounded review, human feedback and
consumer verification. Those mechanisms were retained.

| Existing owner | Effective mechanism retained | Gap addressed |
| --- | --- | --- |
| Root guidance and documentation governance | Conditional routing, dirty-tree preservation, scoped approval, durable ownership | General substantial tasks lacked an explicit outcome/evaluator contract |
| Context audit and routing scenarios | Skill metadata, link/package isolation and read-only routing probes | Structural checks did not execute or bind outcome evidence |
| Performance package and swarm receipt comparator | Environment-qualified paired trials, correctness before timing, minimum effect and p95 | p99-only regressions and sparse p95 evidence could still win |
| UI/design skills and inspector captures | Shared controls, narrow viewports, keyboard behavior, saved references | Search and layout checks missed host-accepted selection and actual Add mutation |

| Review store, game-art corpora, design evidence | Version hashes, append-only feedback, approved/BAD examples, scoped locks | No new store needed; clarified local/project/shared promotion and preference reuse |

The audit sampled the root, Harness contributor/runtime split, Editor/UI ownership,
performance, architecture, shipping, game art, artifact review, managed servers,
user-audit and documentation governance. The metadata/link inventory is broader
than this behavioral sample; it is not a claim that every skill was exercised.

## Independent infrastructure evaluation

An independent evaluator wrote executable adversarial checks against the new
recorder/checker. It found and retained two failures during development:

- An escaping output junction was rejected after an empty output file was already
  created outside the selected root. Output directories are now resolved and
  bounded before descendant directories/files or the command are created.
- A synchronous spawn error left a timer alive and output handles unclosed. Spawn
  and timer setup now share the cleanup boundary; a failing CLI exits promptly.

The suite also exercises stale candidate/contract/artifacts, false success flags,
missing raw evidence, duplicate attempts, human rejection, model-only judgments,
self-authored-only outcome claims, candidate mutation during a check, timeouts,
missing commands, oversized output and path aliases. Separate CLI integration
checks prove that exit zero plus `status: planned` cannot satisfy a declared
`automated-checks-passed` result, and that read-only inspection never executes a
contract command. Unknown contract fields also fail rather than silently dropping
a misspelled acceptance assertion. At this checkpoint, 25 outcome tests pass,
with 88 assertions.

The recorder hashes candidate inputs and actual logs, executes explicit commands
through the existing hidden-process adapter, and verifies hashes on inspection.
Receipts are local records, not signed attestations. It cannot establish honest
human identity, judge relevance, unlisted dependency freshness or arbitrary child
process compliance. The descendant fixture observation is Windows/Bun-specific.
Commands remain responsible for their descendants under existing process policy.

The task's own executable contract was then run through the public CLI: four
criteria (guidance routes, independent negative/CLI/discovery tests, performance
judge consumers and the actual inspector browser journey) produced current
receipts for the same 28-file candidate manifest. Inspection returned
`outcome-demonstrated`, all four criteria passed and no integrity failures.
The browser criterion requires the actual report's completed/after status and
retains authoritative handoffs/final state in its hashed stdout; empty capture
logs alone were replaced with this explicit observable result. Earlier receipts
remain as superseded attempts after the contract amendment. No human approval
criterion or publication claim was added.

## Comparison limits and speed

Two additional fresh agents repeated the architecture and release investigations
after the guidance changes, without reading the baseline reports or this audit.
Architecture again rejected redundant extraction, traced the real hosts and
reported the cache-freshness risk as inferred: 39 distinct tests, package typecheck
and seam lint passed in 333 seconds. An initial origin-boundary test inherited
environment fields; that limitation was recorded and a sanitized rerun passed.
No vault values were inspected or live provider calls made. This establishes
preserved scope/ownership behavior, not a new architecture-quality advantage.

The release repeat ran the actual Harness gate: it failed with six five-second
core test timeouts (five in swarm execution integration, one in its runner).
Those two files passed all 12 tests separately; that does not waive the failed
full run. The UI segment passed 748 tests; the build was skipped. The old archive
also lacks the current Codex bundle and standalone manifest. The final disposition
remains NOT ACCEPTED, with no fresh candidate or first-use/recovery acceptance.
Elapsed time was 457 seconds. Other independent local work was concurrent, so the
timeout cause is unresolved, not attributed to a particular source change.

Baseline investigations took approximately 210 seconds for architecture, 238
seconds for UI/defect, and 283 seconds for performance/release. These are local
elapsed observations, not comparative speed gains. The follow-up tasks included
implementation and additional checks, so they are not a controlled instruction A/B.
No provider token measurements were captured; context byte/word counts are not
reported as token savings.

The baseline agents already challenged premises, used real instruments and found
hidden defects. This evaluation demonstrates repaired product behavior and stronger
executable rejection rules. It does **not** demonstrate a causal or statistically
significant improvement in general model ambition. A broader fixed-model,
fixed-tools, frozen-task campaign remains necessary for that claim.

The broader repository code-style and source-structure gates also fail on
pre-existing work outside these edits; the source-structure gate lists 14
violations. Scoped style/lint checks for the modified code pass. Baselines were
not raised and no broad repository-green claim is made. Five updated skills pass
the skill-creator validator; guidance validation checks 110 files and 42 skills
without errors. The combined guidance/discovery/shipping tests pass 70 tests,
and the directly rerun portable launcher tests pass six tests.

Observed avoidable overhead included guessed Windows wildcard paths, one unavailable
preview host, a local probe dependency-resolution retry and ambiguous log surface
aliases. The managed-server skill now routes preview availability explicitly and
uses exact server IDs. The method catalog returns only the selected domain's
instruments. After a real impact query overwhelmed inspection, `inspect:impact
--summary` was added to the existing discovery tool. The performance comparator
query returned 782,796 bytes in full versus 8,946 bytes in summary, preserving
all 15 consumers, routes and uncertainty notices. This measures JSON retrieval
volume, not model tokens or faster discovery computation (the same scan runs).
No new always-active skill, tracking database, model launcher or
duplicate browser/benchmark platform was added.

## Taste and durable lessons

No new subjective direction was selected or represented as approved. Existing UI
appearance and approved references were preserved. The review skill now explicitly
routes learned choices to local, project or shared ownership with alternatives,
tradeoffs, approval source/date and exact qualities/version. The existing store and
design owners remain authoritative; silence does not promote a candidate.

The important lessons now live in executable owners: tail/completeness regressions
in the performance comparator, a complete component-add journey in the inspector
browser checker, and invalid-evidence/lifecycle cases in context-audit tests. Root
guidance routes outcome-first depth; the portable runtime gets self-contained
principles without monorepo links. CI's existing context-audit test route includes
the new tests automatically.
