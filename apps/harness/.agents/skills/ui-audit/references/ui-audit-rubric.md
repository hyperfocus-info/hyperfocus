# UI audit questions

Use questions relevant to the inspected journey, with evidence from actual states.
This is a set of review prompts, not a checklist that every task must complete.

| Concern | What to inspect |
| --- | --- |
| Orientation | Can users identify the selected object, location, active filters, and next action? |
| Priority | Does hierarchy support the task and expose important status or risk? |
| Control | Can users find commands, understand disabled actions, and predict their scope? |
| Feedback | Does the interface show what changed, what is pending, and what failed? |
| Recovery | Are drafts retained, failures actionable, and details available when needed? |
| Reading | Can users scan critical content without overlap, clipping, or hidden state? |
| Responsive behavior | Does the affected workflow remain usable at supported widths, including open overlays? |
| Accessibility | Are labels, focus order, keyboard operation, contrast, and pointer targets usable? |
| Consistency | Do controls follow the project's established behavior and visual references? |

Prioritize blocked or incorrect actions, then significant friction in core tasks,
then smaller refinements. Use the project's severity convention when one exists;
do not label every clipped optional label as a critical incident. Describe aesthetic
alternatives as suggestions unless a supplied reference establishes the requirement.
