# @hyperfocus/artifact-review

Private Bun host modules for immutable media review. The standalone repository
review CLI and Touch of Death's combined game/audio-review server use the same
manifest validation, HTTP routes and SQLite feedback lifecycle.

Public subpaths are `/create`, `/schema`, `/server`, `/persistence` and `/media`.
`/integrity` provides read-only source-hash and cached-byte inspection using the
same database authority as the host. It reports missing sources separately from
available immutable cached copies and never initializes a database. `/create`
accepts optional `expectedSha256` locks for reproducible reference inputs.
`/constraints` additionally verifies scoped, hashed asset locks against archived
evidence and generated bytes. Touch of Death's builder and locomotion comparison
use it; the [game-art guide](../../scripts/game-art/README.md) owns its commands
and limits. It is a preservation check, not an owner-approval service.
`/direction` is a filesystem-free recipe planner: bind required assets/actions to
bounded family/intent recipes, reject unresolved choices, compare numeric motion
signatures, and require declared evaluation views. Touch of Death calls it in its
real weapon authoring, slice build and review packaging. Game taste and balance
stay in the consumer. The [planning contract](../../scripts/game-art/README.md#intent-before-generation)
owns commands, schema, demonstrated failures and limits.
Recipes use `treatment` for motion, shape, material or environment intent. Legacy
`motion` recipes still compile and retain that output field; conflicting aliases
fail. This is style-neutral binding, not an implementation of every production path.
Evidence defaults can be overridden by named recipe family, so material lighting
studies and environment route views need not inherit motion's contact/phase views.
`createArtifactReviewServer({ manifestPath, publicDirectory, port?, hostname?,
databasePath? })` receives an explicit host-owned UI directory and returns a
server plus `close()`. Hosts close it on startup failure or shutdown. Media bytes
and feedback use `@hyperfocus/review-store`; no application framework is required.

The repository CLI and shared review UI remain in `scripts/artifact-review`.
See its [review guide](../../scripts/artifact-review/README.md) for preparing
manifests, managed hosting, owner annotations and focused native HTTP tests.

From this package, `bun run test` executes the repository review contract,
adapter, persistence and native HTTP tests through the retained public facades.
The local Bun configuration keeps these HTTP tests free of the root DOM preload.
