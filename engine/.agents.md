# Engine Agent Preferences

- Prefer per-frame render sinks and reused draw-data objects over creating fresh objects or arrays inside hot render loops.
- For render-call helpers, prefer optional output sinks so callers can reuse frame arrays without changing public behavior.
- When reducing GC pressure, remove nested point/command/string/object churn, not only wrapper arrays.
- Use `for...of` for arrays and iterables.
- Use `Object.keys()` or `Object.entries()` for object maps.
- Avoid `for...in` unless inherited enumerable properties are intentionally required.
- Compare render experiments with repeated benchmarks and keep drawn-call counts unchanged.
- Store numeric tuning literals as finished values; avoid placeholder arithmetic such as `1 * 1.2` in constants and balance tables.

## Performance Work

- Put machine-independent work budgets in ordinary tests: behavior parity, draw/submission/cull counts, allocations, bytes, cache growth, queue depth, and scaling ratios.
- Use absolute p95/p99 timing as a gate only on a documented reference environment or controlled browser/CPU profile; treat other machines as diagnostic evidence.
- Prefer repeated serial A/B/B/A trials and judge the median p95 across complete trials.
- Treat pooling and output reuse as allocation-control tradeoffs until full-loop frame and memory evidence proves a net win.
- Start from `./docs/engine-performance-hypothesises.md` and `./docs/engine-performance-optimizations.md`; update them when a candidate moves, fails, or becomes default.
- Define the control, candidate, command, repeats, warmup, input scale, flags, and primary metric before editing.
- Run correctness tests before benchmarks; benchmark control and candidates serially, not in parallel.
- Treat subagent or parallel timing output as health evidence only; parent workspace must rerun repeated serial A/B before decisions.
- Judge median p95 first, then p99, average, heap or RSS, payload bytes, draw calls, shader programs, entity counts, and behavior parity.
- Default-enable only clean wins: about 5 percent or better on the target metric with no material regression elsewhere.
- Keep mixed, noisy, behavior-changing, or microbench-only wins opt-in/off until a full-loop bench proves the default path.
- After combining wins, rerun the no-env/default path; do not quote flag-on numbers as default proof.
- Store raw perf artifacts under `./.local/engine-perf/` with date, experiment id, command line, control, candidate, repeats, and summary.
- For render work, follow the `./examples/mmo-skill-demo` pattern for structured calls and viewport culling. Use output sinks or frame pools only when full-loop frame and memory evidence justifies the allocation tradeoff; keep submitted/drawn/culled parity checks.
- For MMO/server work, follow the `./examples/mmo-skill-demo` pattern: counted typed indexes, direct shared-hot reads only with parity tests, lazy static/preencoded chunks, AOI narrowing, dungeon-load benches, and byte telemetry.
- For Three.js work, follow the `./examples/three-arena` pattern: fixed-capacity instancing, near-field animation caps, stable light/shader counts, fixed-grid prop collision, and stress lanes that assert runtime resource drift.
- For high-rate network state, prefer engine binary replication frames and bounded schemas; keep JSON for low-rate lobby, control, debug, and compatibility traffic.
- Use WASM or typed-buffer kernels only when inputs are already numeric and batched. Do not add object-to-buffer copy work unless the benchmark includes that cost and still wins.
- Treat zero-copy decoded payloads as borrowed read-only views unless caller owns the backing buffer; do not retain tiny views that pin large buffers.

## Multiplayer State

- Use engine binary replication frames and schemas for high-rate room snapshots or deltas.
- Keep JSON for low-rate lobby, control, debug, and compatibility messages.
- Do not add game-local binary wire formats when the engine protocol can express the same bounded schema.
- Benchmark protocol changes with multi-client room tests that track bytes/sec, payload size, latency, and entity counts.
